# Soma Nami app

Android app built with Expo SDK 54 as a dev build (native project generated by `expo prebuild`, not Expo Go) and the QVAC SDK for on-device AI.

## Versions

| Package | Version |
|---|---|
| `@qvac/sdk` | 0.22.0 (exact) |
| `react-native-bare-kit` | 0.16.0 |
| Expo SDK | 54 (React Native 0.81) |
| Android | minSdk 29, arm64-v8a only; QVAC needs Android 12+ on arm64 and a physical device (no emulators) |
| Node.js | `^22.21.0 \|\| >=24.9.0` (needed by QVAC's mobile bundler) |

QVAC plugins bundled (`qvac.config.json`): OCR (`ggml-ocr`), TTS (`tts-ggml`), LLM (`llamacpp-completion`).

## Where QVAC is called

- `src/model-store/qvacClient.ts`: `getModelInfo` (is a model on the phone?), `downloadAsset` (fetch it), `cancel`.
- `app.json`: `@qvac/sdk/expo-plugin` bundles the QVAC worker and links its native addons at prebuild.

## Models

Downloaded once, on Wi-Fi, from the models screen. The app won't open the reader until all of them are on the phone, so after that it works in airplane mode.

| Model (QVAC registry constant) | Used for | Size |
|---|---|---:|
| `OCR_CRAFT` | finding text in a photo | 83 MB |
| `OCR_LATIN` | reading Latin-script text | 15 MB |
| `TTS_MULTILINGUAL_SUPERTONIC3_Q4_0` | English voice | 85 MB |
| `TTS_T3_MULTILINGUAL_CHATTERBOX_Q4_0` | Swahili voice, part 1 | 345 MB |
| `TTS_S3GEN_MULTILINGUAL_CHATTERBOX_Q4_0` | Swahili voice, part 2 | 788 MB |
| `QWEN3_1_7B_INST_Q4` | answering questions about the label | 1,057 MB |
| **Total** | | **≈2.4 GB** |

The list is `src/model-store/manifest.ts`; it follows `docs/scope.md` §1 and may change after the C2 spike.

## Develop

```bash
cd mobile
npm ci
npm run check                 # lint, typecheck, unit tests
npx expo prebuild --platform android --no-install
npx expo run:android --device # needs Android SDK, NDK 29.0.14206865, JDK 17 and a USB-connected phone
```

Run `expo prebuild` again after any `npm install`: reinstalling unlinks QVAC's native addons.

### Notes for contributors

- Expo SDK 54 and `@qvac/sdk` 0.22.0 are pinned on purpose (QVAC's Expo plugin is built against SDK 54). Don't upgrade during the hackathon.
- `android/` and `ios/` are generated and ignored. Configure native behaviour in `app.json`, `qvac.config.json` or config plugins.
- Adding a QVAC capability means adding its plugin to `qvac.config.json` and its exact-version Android/iOS prebuild packages to `package.json` (for example `@qvac/tts-ggml-android-arm64`); the APK build fails with `HOST_PREBUILDS_MISSING` otherwise.
- Nothing may start a read unless `canRead(state)` (`src/model-store/modelsState.ts`) is true. `src/AppShell.tsx` enforces it.
- Unit tests never import `@qvac/sdk` (it needs the native worker); they use `FakeModelClient` from `src/model-store/testing.ts`.
- `api.expo.dev` is blocked from the Bond VPS sandbox, so `npx expo install` fails there; use the version listed in `node_modules/expo/bundledNativeModules.json` with npm.

## Install the dev APK on a phone

1. On GitHub, open **Actions → Android dev APK**, pick the latest green run on `main` (or run it with **Run workflow**).
2. Download the `soma-nami-dev-apk` artifact (a zip) and unzip it to get `soma-nami-dev-<commit>.apk`.
3. Copy it to the phone, open it, and allow "Install unknown apps" for the app you opened it with.

The APK is standalone (JavaScript bundled in, signed with the Android debug key). It is for testing, not for the Play Store.
